# SUBIT-COMPUTER SPECIFICATION v0.1

**Статус:** формальна специфікація обчислювального ядра  
**Сумісність:** узгоджено з SUBIT-∞ v5.2  
**Призначення:** визначити мінімальну логіко-динамічну архітектуру SUBIT-машини до апаратної реалізації

---

## 0. Преамбула

Цей документ фіксує сім рівнів формальної моделі SUBIT-комп’ютера:

1. **SUBIT Atom** — атомарна чотиризначна клітинка.  
2. **SUBIT-64 State** — морфологічний простір станів.  
3. **Extended State** — стан разом із правилом і контекстом.  
4. **Transition Grammar** — повна динаміка розширеного стану.  
5. **Instruction Set / SUBIT-ALU** — операції над морфологічними станами.  
6. **Trajectory Model** — послідовність розширених станів.  
7. **Analytical Layer** — Ω, dΩ, P(τ), ⊥.

SUBIT-комп’ютер визначено як **морфодинамічну обчислювальну систему**: машину, що обчислює переходи між структурованими станами можливого, а не лише оперує числами.

---

## 1. SUBIT Atom

### 1.1. Множина значень

```
𝔸 = {T, F, B, N}
```

де:

- T — істина;
- F — хиба;
- B — обидва значення водночас (суперечність);
- N — жодне значення (невизначеність).

Додаткова семантична реалізація:

```
{ME, WE, YOU, THEY}
```

є ізоморфною до 𝔸, але не ототожнюється з логічними значеннями.

### 1.2. Білаттис Белнапа

На 𝔸 задано два незалежні часткові порядки.

**Істиннісний порядок:**

```
F <_t N <_t T
F <_t B <_t T
```

**Інформаційний порядок:**

```
N <_i F <_i B
N <_i T <_i B
```

### 1.3. Логічні операції

Операції визначаються через обидва порядки.

**Заперечення (¬):**

```
¬T = F
¬F = T
¬B = B
¬N = N
```

**Кон’юнкція (∧):**

| ∧ | F | N | T | B |
|---|---|---|---|---|
| **F** | F | F | F | F |
| **N** | F | N | N | F |
| **T** | F | N | T | B |
| **B** | F | F | B | B |

**Диз’юнкція (∨):**

| ∨ | F | N | T | B |
|---|---|---|---|---|
| **F** | F | N | T | B |
| **N** | N | N | T | T |
| **T** | T | T | T | T |
| **B** | B | T | T | B |

**Виключна диз’юнкція (⊕):**

```
x ⊕ y := (x ∧ ¬y) ∨ (¬x ∧ y)
```

### 1.4. Фізичне кодування

Для апаратної реалізації субіт подається парою (p, q):

| Субіт | p | q | Двійковий код |
|---|---:|---:|---:|
| T | 1 | 0 | 10 |
| B | 1 | 1 | 11 |
| F | 0 | 1 | 01 |
| N | 0 | 0 | 00 |

Формули для вентилів:

```
p_out(¬) = q_in
q_out(¬) = p_in

p_out(∧) = p_a · p_b
q_out(∧) = q_a + q_b

p_out(∨) = p_a + p_b
q_out(∨) = q_a · q_b
```

## 2. SUBIT-64 State

### 2.1. Простір станів

```
S₀ = 𝔸³ = 𝔸_WHO × 𝔸_WHERE × 𝔸_WHEN
```

Кожен стан — впорядкована трійка:

```
s = (w, h, t)
```

де:

- w ∈ 𝔸 — координата WHO;
- h ∈ 𝔸 — координата WHERE;
- t ∈ 𝔸 — координата WHEN.

### 2.2. Потужність

```
|S₀| = 4³ = 64
```

Це **морфологічний простір**, а не простий 6-бітний регістр. Фізична інформаційна ємність — 6 біт, але семантична геометрія — декартів простір трьох чотиризначних осей.

### 2.3. Кодування

Кожен стан кодується трьома субітами, тобто шістьма фізичними бітами:

```
s = (p_w, q_w, p_h, q_h, p_t, q_t)
```

Для нотації можна використовувати гексаграмну відповідність, але формально вона не є частиною специфікації.

---

## 3. Extended State

### 3.1. Означення

```
Ŝ_t = (S_t, R_t, C_t)
```

де:

- S_t ∈ S₀ — морфологічний стан;
- R_t ∈ 𝓡 — поточне правило переходу;
- C_t ∈ 𝓒 — контекст (історія, горизонт, зовнішні умови).

Правило **не зобов’язане фізично зберігатися разом зі станом**. Воно є частиною **розширеного обчислювального стану**.

### 3.2. Простори

- 𝓡 — множина правил. У v0.1 𝓡 вважається скінченною або перелічуваною множиною функцій:

```
ρ : S₀ × 𝓒 → S₀
```

- 𝓒 — множина контекстів. У v0.1 контекст може бути:
  - порожнім;
  - скінченною історією попередніх станів;
  - обмеженим лічильником горизонту.

## 4. Transition Grammar

### 4.1. Фундаментальна динаміка

```
Ŝ_t+1 = G(Ŝ_t)
```

де G — **граматика переходу**, тотальна функція:

```
G : S₀ × 𝓡 × 𝓒 → S₀ × 𝓡 × 𝓒
```

### 4.2. Компонентне визначення

```
G(s, ρ, c) = (s′, ρ′, c′)
```

де:

```
s′  = ρ(s, c)
ρ′  = μ(s, ρ, c)
c′  = ν(s, ρ, c)
```

Тут:

- ρ — функція, що обчислює наступний морфологічний стан;
- μ — **метаоператор**: обчислює наступне правило;
- ν — **оператор контексту**: оновлює контекст.

### 4.3. Аксіоми

1. **Детермінованість:** G — тотальна функція.  
2. **Замкненість:** для всіх Ŝ ∈ S₀ × 𝓡 × 𝓒 значення G(Ŝ) належить тому самому простору.  
3. **Ієрархія самореференції:** правило ρ може змінюватися метаоператором μ залежно від поточного стану, правила і контексту.

## 5. Instruction Set / SUBIT-ALU

SUBIT-ALU оперує морфологічними станами S₀, а не числами.

### 5.1. Базові морфологічні оператори

Нехай A, B ∈ S₀, де

```
A = (a_w, a_h, a_t)
B = (b_w, b_h, b_t)
a_i, b_i ∈ 𝔸
```

#### Логічні покомпонентні операції

```
¬A  := (¬a_w, ¬a_h, ¬a_t)

A ∧ B := (a_w ∧ b_w, a_h ∧ b_h, a_t ∧ b_t)

A ∨ B := (a_w ∨ b_w, a_h ∨ b_h, a_t ∨ b_t)

A ⊕ B := (a_w ⊕ b_w, a_h ⊕ b_h, a_t ⊕ b_t)
```

#### Проекція

```
π_i(A) := a_i,   i ∈ {WHO, WHERE, WHEN}
```

#### Ротація

```
ROTATE(A) := (a_h, a_t, a_w)
```

#### Злиття (MERGE)

```
MERGE(A, B) := (a_w ∧ b_w, a_h ∨ b_h, a_t ⊕ b_t)
```

*Примітка:* у v0.1 MERGE визначено як фіксована морфологічна комбінація; у пізніших версіях може бути параметризованим.

#### Розщеплення (SPLIT)

```
SPLIT(A) := (a_w, a_h, a_t)
```

Повертає три окремі субіти.

#### Морфологічна відстань

```
d_M(A, B) := #{ i ∈ {w,h,t} : a_i ≠ b_i }
```

### 5.2. Оператор переходу

```
TRANSITION(s, ρ, c) := π_S( G(s, ρ, c) )
```

де π_S — проекція на морфологічну компоненту.

## 6. Trajectory Model

### 6.1. Траєкторія

Для заданого початкового розширеного стану Ŝ₀:

```
τ(Ŝ₀) = (Ŝ₀, Ŝ₁, Ŝ₂, …)
```

де Ŝ_t+1 = G(Ŝ_t).

### 6.2. Хвіст траєкторії

```
tail_k(τ) = (Ŝ_k, Ŝ_k+1, Ŝ_k+2, …)
```

### 6.3. Множина атракторів

```
Fix(G) = { Ŝ ∈ S₀ × 𝓡 × 𝓒 : G(Ŝ) = Ŝ }
```

---

## 7. Analytical Layer

### 7.1. Канонічна функція P(τ)

На відміну від безпосереднього застосування Ω до траєкторії, аналітичний шар спершу будує множину, придатну для класифікації.

#### Визначення ω-границі

Для скінченного S₀ × 𝓡 × 𝓒:

```
ω(Ŝ₀) = { Ŝ ∈ S₀ × 𝓡 × 𝓒 : ∃ (t_k) → ∞,  Ŝ_t_k = Ŝ }
```

#### Момент входження

```
m(Ŝ₀) = min{ t ≥ 0 : Ŝ_t ∈ ω(Ŝ₀) }
```

Якщо m не вдається обчислити за заданий ресурс, P(τ) = ⊥.

#### Побудова P(τ)

```
P_pt(τ)    := { Ŝ_m(Ŝ₀) }

P_nbhd(τ, ε) := B_ε(Ŝ_m(Ŝ₀)) ∩ (S₀ × 𝓡 × 𝓒)
```

де B_ε — куля в метриці d_M.

### 7.2. Класифікатор Ω

Для множини P ⊆ S₀ × 𝓡 × 𝓒:

```
Ω(P) =
    STABLE      якщо G(P) = P
    METASTABLE  якщо G(P) ⊊ P
    CYCLIC      якщо ∃ k > 1: Gᵏ(P) = P  і  G(P) ≠ P
    CHAOTIC     в інших випадках
```

Для траєкторії:

```
Ω(τ) =
    ⊥                         якщо P(τ) = ⊥
    Ω(P_pt(τ))                якщо Ω(P_pt(τ)) ∈ {STABLE, CYCLIC}
    Ω(P_nbhd(τ, ε))           для перевірки METASTABLE
```

### 7.3. Семантична ультраметрика dΩ

Для двох траєкторій τ, σ:

```
n₀(τ, σ) := min{ t ≥ 0 : Ω(tail_t(τ)) ≠ Ω(tail_t(σ)) }

dΩ(τ, σ) :=
    2^(−n₀)   якщо n₀ визначено
    0         якщо Ω(tail_t(τ)) = Ω(tail_t(σ)) для всіх t
```

Якщо хоча б один із класифікаторів дорівнює ⊥, dΩ повертає ⊥.

### 7.4. Властивості

- dΩ задовольняє сильну нерівність трикутника.  
- (S₀ × 𝓡 × 𝓒, d_M) є ультраметричним простором.  
- Ω утворює алгебру Гейтінга з порядком:

```
CHAOTIC < CYCLIC < METASTABLE < STABLE
```
